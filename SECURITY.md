# Security Policy

## Reporting a vulnerability

If you discover a security vulnerability in these Terraform modules, please
report it privately. **Do not open a public issue for security problems.**

Preferred method: use GitHub's
[private vulnerability reporting](https://github.com/pierrehanne/terraform-services/security/advisories/new)
("Report a vulnerability" under the **Security** tab). This keeps the report
confidential until a fix is available.

Please include:

- The affected module(s) and version/tag.
- A description of the issue and its potential impact.
- Steps to reproduce, or a minimal Terraform configuration that demonstrates it.

## What to expect

- We aim to acknowledge reports within a few business days.
- We'll work with you to confirm the issue and determine its severity.
- Once a fix is ready, we'll release it and credit you (unless you prefer to
  remain anonymous).

## Scope

These modules aim to be secure by default (encryption enabled, least-privilege
IAM, no public exposure unless explicitly opted in). Reports that fall in scope
include, for example:

- Insecure defaults that expose data or grant excessive permissions.
- Overly permissive IAM policies generated by a module.
- Missing encryption where a resource supports it.

Misconfiguration on the consumer side (e.g. explicitly setting a variable to a
public/insecure value) is generally out of scope, though we welcome
documentation improvements that make secure usage clearer.

## Supported versions

Security fixes are applied to the latest released tag. Please upgrade to the
most recent version before reporting, and pin modules to a released tag rather
than tracking `main`.
